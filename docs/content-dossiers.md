# 内容档案组件

动机：原先仅给主题和研究方向补图，没有解决作者实践、关注点、首页近期文章、归档和论文主体仍各自使用简单列表的问题。这里统一的是内容的承载方式与维护入口；图片按内容需要选用。

## 共同形式

`src/components/discover/ContentDossier.astro` 与 `src/styles/content-dossier.css` 管理纸面、橙色定位线、编号题签、标题与正文、资源入口和原生展开区。页面样式只负责不同内容的比例和排列。

- `feature`：项目档案，侧边题签与正文分开，适合简短的实践说明。
- `compact`：文章、归档与论文记录，用界面字体承载长标题和摘要。
- `note`：研究问题与写作范围，使用略暖的纸面和有序内容。

有图时使用 `media` slot；没有图片时直接让正文占满可用宽度。Astro 的条件命名 slot 即使内容为空也可能存在，因此由可选数据控制图片时，须传入 `hasMedia={Boolean(source.cover)}`，避免留下空列。

其他 slot：`meta` 是日期/作者/发表信息，`leading` 是首页的日期主题栏，`footer` 放资源链接，`details` 放次要的关联资料。标题和核心说明始终可见，不能为了让卡片整齐而藏进展开区。

`asLink` 用于首页整篇可点的文章条目，此模式不放其他链接或展开控件。其余记录是独立 `article`，图片、标题和阅读入口是各自的链接。

## 新内容如何接入

| 内容 | 数据入口 | 自动呈现 |
|---|---|---|
| 作者项目 | `SITE_AUTHOR_PROFILE.practiceHighlights` | 标题、说明、可选题签 `label`、相关内容 `related` |
| 当前关注／博客范围 | `SITE_AUTHOR_PROFILE.currentFocus` / `blogScope` | 自动编号的研究便笺 |
| 首页近期文章 | `posts` collection 与既有首页选择器 | 原封面、日期、主题、标题、完整摘要 |
| 归档 | `posts` collection 与既有年月分组 | 按时间排序的图文档案 |
| 论文 | `papers` collection | 年份、状态、完整作者、摘要、资源和可展开引用 |

新增记录主要填写已有数据，不需要为每篇内容设计单独的 HTML/CSS。项目的 `related` 是阅读关联，不表示链接目标就是该项目的成果。不要编造进度、成绩、实验图或公开代码地址。

## 视觉反馈后的修正

首版截图出现两个问题：作者项目为了等高留下人工空白；论文的空图片 slot 产生了一列空白。第二版将项目改为连续侧题签档案，并显式控制可选图片。归档保留原年月账本，将标题与图版顶边对齐，避免首篇标题被大图的垂直居中推迟；原封面完整 `contain`，不截断图中文字。

手机复核继续发现首页两条标题的孤字尾行，以及作者无元信息的节标题被空栏挤窄。对短标题使用平衡断行，对短说明使用 pretty 断行；SectionHead 只在确有计数/入口时生成元信息栏。保留源文字和字号，并使用 Range 测量实际文字行进行回归。

原建筑首页首屏、主题轮播、漫游关系、文章阅读、目录、旁注、评论以及胶囊导航维持既有契约。
