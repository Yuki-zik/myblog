# 阅读字级与编号比例

2026-10-18。用户三张截图指出章节编号过小、行内代码与正文不协调，以及旁注中衬线/等宽/编号和长网址混杂。方案沿用已确认的白色图纸与橙色导航，以正文尺度为基准协调字级。

## 设计依据与实现

| 层级 | 修改前 | 修改后 | 作用 |
|---|---|---|---|
| 正文 | 18.24px / 1.88 | 同一基准 | 连续阅读与行长 |
| 主章节 / 编号 | 25px / 12px | 26px / 20.8px | 编号与标题共同导航，同一基线 |
| 子章节 / 编号 | 19.81px / 12px | 21px / 17.64px | 编号不再像上标，保留清晰层级 |
| 旁注正文 | 13.92px / 1.76 | 15.5px / 1.75 | 次级信息可以直接阅读 |
| 旁注编号 / 类型 | 13.12px Georgia / 10.4px UI | 15px UI / 12px UI | 与章节、导航使用同族数字 |

标题和连续文字使用 Source Serif 4 / Noto Serif SC 的阅读衬线组合；编号、类型标签使用系统 UI 字体与等宽数字。章节编号分别为标题的80%和84%。行内真实代码保留等宽语义，字号为正文的87.5%，移除描边、减少上下内边距，避免连续文字被厚框打断。

字体协调也取决于内容语义：设计说明书中的品牌、原则名和章节名恢复普通文本；路径、组件名、状态值等代码内容继续使用等宽。来源以可读名称链接，避免裸网址在旁注中反复折行。Markdown原文接口直接读取同一文件，内容保持同步。

旁注的重复箭头是实际渲染缺陷。GFM的HAST使用空字符串表示存在型data属性，插件原来只接受true，导致回链没有被移除。现在接受true或空字符串；旁注数字按钮继续返回首次正文引用，重复引用共享同一旁注，note/ref/paragraph ID契约保留。两个新增单测覆盖camel/dashed空串标记、多条回链与外部来源保留。
