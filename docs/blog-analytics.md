# 博客访问统计：设计与口径

## 产品边界

目标是评估哪些内容、渠道和阅读功能值得持续投入。统计采用成熟的
GoatCounter 2.7.0，自托管 SQLite；已有 VPS 453 MiB 内存，不为统计增加
订阅费用、Docker 或数据库服务。前端零新增 npm 依赖。

公开侧：文章标题辅助信息显示“统计访问”，中英文分开。未收到有效结果
显示横线，绝不填充示例数字或把请求失败解释为零。后台侧：按日期、文章、
来源、浏览器/系统、国家、语言查看聚合趋势，事件单独列出，可导出聚合数据。
后台需登录；公开计数接口只接受文章路径，不暴露 TOTAL 或行为事件计数。

## 数据定义

- 统计访问：同一页面在最长 8 小时的临时会话内去重。不能解释为精确人数、
  原始刷新次数，或跨设备 UV。各文章访问数相加也不等于全站独立人数。
- 数据覆盖：只统计主动允许且未发送 DNT/GPC 的读者。拒绝、广告拦截、网络
  故障和浏览器自动化会造成缺失；不可称为全部实际流量。
- 文章统计：`/posts/slug` 与 `/en/posts/slug` 分开；不会补造上线前历史。
- 来源：仅外部域名，或白名单 `utm_source` / `utm_campaign` 标签。普通查询
  参数、搜索词、邀请码、邮件地址、片段和来源完整路径均不上报。
- `read_25/50/75/90`：可见、聚焦且近期有操作，累计至少 10 秒后到达该深度。
  它是阅读参与信号，不代表理解或读完。每页面生命周期去重。
- `active_30s/60s/180s`：前台活动时间估计，60 秒无操作暂停累计；不等于精确
  注视时间。不采集按键内容、鼠标轨迹或录像。
- `bionic_on/off`、`language_switch`：功能使用，不据此宣称提高理解能力。
- `outbound_telegram/discord/github/email/rss/external`：点击类别，不是入群、
  新增订阅、付费或真实收入；不采集完整目标地址。
- 事件与流量分别统计，主流量图 `no-events=true`。不能把行为事件加成 PV。
- 公开计数由上游缓存，更新延迟最长约 4 小时；后台写入通常按 10 秒缓冲。

## 隐私与实现

默认关闭，页脚和 `/privacy`、`/en/privacy` 可以修改。偏好只存本地
`analytics-consent-v1`，DNT/GPC 优先，不设置追踪 Cookie 或跨站用户 ID。
加载上游脚本之前设置 `no_onload/no_events`，封装 `get_data` 清除查询与屏幕
宽度，再以 `fetch` 的 `keepalive`、`credentials:omit`、`referrerPolicy:no-referrer`
发送。直接使用 sendBeacon 会在同源 Referer 中携带查询，因此不能直接换回。

只在正式主域及镜像域收集；本地、预览、404、隐私页、搜索接口不会计数。
自动浏览器默认跳过。测试把正式主域映射到本地构建，拦截全部上报，绝不向
生产统计库注入测试流量。仿生阅读、目录、评论初始化彼此独立。

服务在境外 VPS，页面已有明确说明；无地区/IP地址展示。GoatCounter 短暂
使用 IP+UA 进行八小时会话判断，正常访客的原始 IP/完整 UA 不写统计数据库。
国家、浏览器等按聚合表保存；不启用逐条浏览历史，保留 730 天。
这项技术配置不等于对所有司法辖区作出合规保证。

## 架构与维护

`BaseLayout` 标明可信路由 → 共用 client → 允许后加载固定版本 tracker →
同源 `/_analytics/count` → Vercel rewrite / 镜像 Nginx → localhost GoatCounter。
公开文章计数单独只读；详细仪表盘在 `/analytics` 登录，管理 API 不经前端。
采集端失败最多损失统计，正常阅读、目录、评论与仿生模式不受阻断。

部署、备份与恢复见 `deploy/analytics/README.md`。源码不包含账户密码、API
令牌、数据库或访问日志。管理员凭据仅放作者可信设备的私有文件。

## 验收

必须通过：模型/配置单元测试；SQLite WAL 在线备份与恢复测试；中英隐私页、
允许/拒绝、DNT/GPC、请求头脱敏、前台活动阈值、事件去重、外链分类、故障
降级及手机明暗模式浏览器测试；原有 bionic/TOC/Waline 回归；全量 CI。
最终上线证据与准确测试结果写入 visual-history/任务记录，未验证项不得写通过。

## 后续增长分析

先收集真实数据，再判断文章参与深度、渠道质量与外链点击。没有接入会员或
交易系统之前，不生成“新增订阅”“付费率”“收入归因”等虚假指标。不部署
定时 AI 报告、群发或收费服务；这些应基于可用数据和用户单独授权扩展。
