# Agent 工作观察站

## 目的与边界

`/agents` 持续观察一个人能并行推进多少独立任务、得到哪些可验收成果，以及投入多少人工时间。中文主页保留轻量入口；独立页面的每项数据各有一个外形与交互不同的小挂件。公开研究是参照，个人观测是另一份数据；两者不能拼成同一条生产力曲线。

初始版本包含六条可核对的研究记录，日级实测仍为空。2026-10-25 按作者请求补入六项公开交付的历史回溯，方法与来源见 [历史回溯维护](agent-history.md)。页面中的“待记录”表示尚无测量，不能替换成 0，也不能用展示数据补齐历史。页面没有自动访问私人会话，也没有自动采集、定时更新或后台写入功能。

## 实现

- `src/data/agent-observatory.json`：经作者确认后公开的日期与任务记录。
- `src/lib/agents/observatory.ts`：类型、校验、七日观测窗口汇总和带出处的研究条目。
- `src/pages/agents.astro`：复用既有 BaseLayout / DiscoverShell 的静态页面。
- `src/components/agents/AgentObservatoryWidget.astro`：中文主页的短入口。
- `src/components/agents/AgentInstrumentDesk.astro` 与 `instruments/*.astro`：四个独立挂件，分别呈现任务轨道、交付票据、注意力表盘与返工卷尺。
- `src/components/UiControllers.astro` 的 `initAgentInstruments()`：初始化原生滑杆、翻页、阶段选择与复位，不写入实测数据。
- `src/styles/agent-observatory.css` 与 `src/styles/agent-instruments.css`：页面/入口和挂件各自的局部样式，沿用既有主题变量。
- `public/agent-observatory-template.json` 与 `public/agent-observatory-log-template.md`：空数据与人类可读记录模板。

采用既有 Astro、原生 range/button/details 和 CSS/SVG；交互接入现有共享控制器，不新增框架、图表包、数据库、依赖或独立客户端入口。原六个导航项与阅读页运行时保持原有契约。`/agents` 纳入直接 sitemap，由 Astro sitemap 集成同步生成。

## 交互挂件 · 2026-10-24 调整

用户反馈首版面积过大，要求每项数据一个挂件，外观可不同并强调交互。新版将研究、记录与方法折叠到下方；桌面采用两列，手机单列。首页只保留约一行高度的入口。

任务轨道可拖动时间游标；交付票据可翻页并展开验收标准；注意力表盘可选择布置、审核、返工；返工卷尺可拖动和归零。四项个人实测由同一已校验的七日汇总服务端渲染，交互不改变实测值。每件标注“交互示意”，示意只用于解释口径，不保存、不发送、不宣称已经观察到这些工作。当前每日记录没有任务起止时间，因此不会从并行峰值推造真实时间轴。

无 JavaScript 时，实测与说明继续显示，交互控件禁用；原生详情和模板仍能使用。键盘可操作滑杆及按钮，不依赖拖拽。

## 每天如何记录

先在 Markdown 模板里记下日期、同时推进的独立任务峰值、人工总分钟、其中返工分钟，以及当天是否完整记录了所有任务。公开前确认内容，再填写 JSON。时间使用记录者选择的本地日历日，并在整个观测系列中保持一致。

人工总时间包含定义目标、补充上下文、检查、纠错、协调和整合。同一分钟不能重复记到多个并行任务；返工是总人工时间的一部分。Agent 运行时长、排队时间和人类时间分别理解。

任务以事先约定的验收目标计数。一个目标的五个子 Agent 仍是一项任务；重试和修改沿用原 ID。代码、研究、写作与运维任务保留类型，结果附可复核的交付链接。研究任务可以交付经过复核的负结果。失败、放弃和待验收工作也要保留。

`taskLogComplete` 只在当天任务记录完整时填写 true。缺失的测量填 null，真正观察到的零填 0。成本和模型/工具变化先放在每日 note，注明金额、币种及实际 API 账单或订阅分摊口径；第一版不把不同成本口径相加。

## 汇总与解释

窗口锚定最后一个已记录日期，向前包含七个自然日；页面明确显示窗口，不冒称实时“本周”。并发峰值取最大值，不能按天累加，也不能称为人的最大管理能力。

人工与返工是已记录日的合计，缺日时显示覆盖提示。已记录日自身有缺失值时，对应合计保留未知。验收成果按唯一任务 ID 统计，记录覆盖不足时不宣称已得到完整总量。完整的零与尚未记录严格区分。

不同工作大小与验收标准不同。跨周交付还存在投入和产出错期。独立页面的四个挂件各自呈现一个实测值，不计算综合分数、“等效员工”或“生产率提高几倍”。

## 怎样检验生产力

积累记录后，在同类任务、相近规模和一致验收标准下，比较单 Agent 与多 Agent；保留失败、审核及返工成本。条件允许时交替分配工作模式，记录真实对照。主观估计的“自己要做多久”只作为主观基线。

同时记录能力扩展：本周完成了哪些过去无暇尝试的工作。增加低价值产出与增加重要交付需要分别评价。模型升级、自动测试、提示模板、上下文管理或拆分方式改变时，在 note 留下日期，便于解释变化。

## 研究维护

每条证据保留来源链接、发布或修订日期、证据类型与适用边界。月份级日期保留月份，不填造具体日。论文修订版本改变样本量时更新同一条目，并写明版本。METR time-horizons 展示页在 2026-09-08 后已停止主动维护，只作为历史来源；原研究的 50% 时间跨度是任务的人类专家耗时，不是 Agent 无人干预运行时间。

本页是持续记录的起点。首版不提供“2022 年每人 1 个、2026 年每人 N 个 Agent”曲线，因为尚无可比较的个人/行业测量支持这一数列。
